# Project Structure

**Analysis Date:** 2026-06-20

## Directory Layout

```
portfolio2026/                  # Project root
├── Portfolio.dc.html           # The entire portfolio page (template + logic + styles)
├── support.js                  # DC runtime — framework bootstrap, React loader, compiler
├── image-slot.js               # <image-slot> Web Component — drag-and-drop photo slots
│
├── assets/
│   └── profile.png             # Author profile photo (used as default src for image-slot)
│
├── uploads/
│   └── rund.PNG                # Uploaded asset (likely a project image or logo)
│
├── .thumbnail                  # Design-tool thumbnail (binary, not source code)
│
└── .planning/
    └── codebase/               # GSD mapper output (this document lives here)
        ├── ARCHITECTURE.md
        └── STRUCTURE.md
```

**.image-slots.state.json** — generated at runtime by `image-slot.js` when images are
dropped in the design-tool host environment. Not committed; lives at project root when
present.

## Key Files

| File | Purpose |
|---|---|
| `Portfolio.dc.html` | Single page: HTML template inside `<x-dc>`, inline CSS inside `<helmet><style>`, bilingual content (`CONTENT` map), skills data (`SKILLS` array), all interactive logic (`class Component extends DCLogic`) inside `<script data-dc-script>`. |
| `support.js` | DC runtime (generated, ~1 500 lines). Loads React 18 from CDN, parses `.dc.html` documents, compiles `{{ expr }}` templates into React render functions, evaluates `DCLogic` class, manages a component registry, handles `<sc-for>`, `<sc-if>`, `<helmet>`, `<x-import>` directives. Do not edit by hand — comment at top says rebuild via `cd dc-runtime && bun run build`. |
| `image-slot.js` | Self-contained Web Component (`<image-slot>`). Registers the custom element, manages a shared sidecar JSON store for persisted image crops, handles drag-and-drop, click-to-browse, reframe (pan + scale) UI. Loaded inside `<helmet>` so the runtime injects it into `<head>` on mount. |
| `assets/profile.png` | Author's profile photo. Referenced as `src="assets/profile.png"` in the `#hero-photo` and `#about-photo` `<image-slot>` elements. |
| `uploads/rund.PNG` | An uploaded image asset. Not currently referenced in any `<image-slot>` `src` attribute — likely intended as a project screenshot or logo. |
| `.thumbnail` | Binary file generated by the design-tool host. Not source code. |

## Naming Conventions

**Files:**
- Main page: `[Name].dc.html` — the `.dc.html` extension signals a DC Design Component file to the runtime and any hosting tools.
- Runtime script: `support.js` — flat, lowercase, single word.
- Web Component script: `[component-name].js` — matches the custom element tag name (`image-slot` → `image-slot.js`).
- Static assets: `lowercase.ext` or `CamelCase.EXT` (no enforced rule; both forms appear: `profile.png`, `rund.PNG`).

**Identifiers inside `Portfolio.dc.html`:**
- Section IDs: lowercase (`#top`, `#about`, `#skills`, `#portfolio`, `#contact`).
- `<image-slot>` IDs: `[scope]-[subject]` pattern (`hero-photo`, `about-photo`, `proj-join`, `proj-pollo`, `proj-pokedex`).
- Ref names: camelCase, suffixed with `Ref` (`rootRef`, `canvasRef`, `roleRef`, `progressRef`, `emailRef`).
- Content keys: camelCase dotted paths (`t.nav.about`, `t.hero.cta`, `t.contact.sent`).
- Setup methods: `setup[Feature]()` (`setupCanvas`, `setupCursor`, `setupReveal`, `setupParallax`, `setupProgress`).

## Module Boundaries

**`Portfolio.dc.html` owns:**
- All visible UI (HTML structure, inline CSS custom properties, section layout).
- All bilingual copy (`CONTENT.de`, `CONTENT.en`).
- All skills data (`SKILLS` array).
- All page-level interactions (canvas animation, cursor glow, scroll reveal, parallax, progress bar, typewriter, lang toggle, contact form submit).
- Component lifecycle (`componentDidMount`, `componentWillUnmount`).

**`support.js` owns:**
- Framework internals: template compilation, expression resolution, component registry, React integration, `<sc-for>` / `<sc-if>` / `<helmet>` directive implementations.
- Should never contain portfolio-specific logic. Treat as a black-box runtime.

**`image-slot.js` owns:**
- Photo slot UI and UX (empty state, drag-over highlight, reframe handles, Replace/Remove controls).
- Sidecar JSON persistence (`/.image-slots.state.json`) via `window.omelette.writeFile`.
- Image downscaling (canvas → WebP, max 1 200 px).
- Operates independently of the DC runtime — it is a plain Web Component registered via `customElements.define`.

**`assets/`** — static files served alongside the HTML. Images only; no scripts.

**`uploads/`** — user-uploaded files. Intended for project screenshots and similar media.
Files here are referenced (or should be referenced) from `<image-slot src="...">` attributes
in `Portfolio.dc.html`.

## Summary

The project is a flat, zero-build structure: one HTML page, two JavaScript files, and two
asset folders. All portfolio content and behaviour live inside `Portfolio.dc.html`; the
runtime (`support.js`) and the photo-slot component (`image-slot.js`) are supporting
infrastructure that should be treated as library code.
