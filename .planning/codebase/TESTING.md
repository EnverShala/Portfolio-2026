# Testing

**Analysis Date:** 2026-06-23

## Test Setup

There is no automated test suite. This project has:

- No `package.json` (no npm, no node_modules)
- No test runner (no Jest, Vitest, Playwright, Cypress, or equivalent)
- No lint configuration (no ESLint, Biome, Prettier config files)
- No CI pipeline configuration (no `.github/workflows/`, no Netlify/Vercel build hooks)
- No TypeScript compiler (source is plain JS/HTML; `support.js` is a pre-compiled artifact)

All validation is manual and visual, performed directly in a browser.

## Validation Approach

**The workflow for making and verifying a change is:**

1. Edit `Portfolio.dc.html` (and/or `image-slot.js` / `support.js` as needed).
2. Open `Portfolio.dc.html` directly in a browser — the x-dc runtime (`support.js`) boots React, parses the `<x-dc>` block, and renders the component in-page. No build step required for the source file.
3. Visually verify the change across the targeted viewport widths (see breakpoints in CONVENTIONS.md).
4. When satisfied, manually copy the edited file(s) to `dist/` to keep the production build in sync.

**The `dist/` directory is the production artifact** — it is manually maintained, not generated by a build tool. There is no script to automate the sync between source and `dist/`.

**Commit messages serve as a change log and implicit regression baseline.** The convention `fix(scope): description` (e.g. `fix(hero): center content vertically on 481–765px`) documents what was intended so that future regressions can be identified by reading git history.

## Browser Compatibility Notes

The codebase uses several modern browser APIs that gate compatibility:

| Feature | Used in | Minimum requirement |
|---|---|---|
| `min-height: 100svh` | `Portfolio.dc.html` hero section | Chrome 108+, Safari 15.4+, Firefox 101+ |
| CSS custom properties | Throughout all inline styles | All modern browsers |
| `IntersectionObserver` | `setupReveal()` in `Portfolio.dc.html` | Chrome 51+, Safari 12.1+, Firefox 55+ |
| `ResizeObserver` | `image-slot.js` | Chrome 64+, Safari 13.1+, Firefox 69+ |
| Shadow DOM (open mode) | `image-slot.js` | Chrome 53+, Safari 10+, Firefox 63+ |
| `customElements.define` | `image-slot.js` | Chrome 54+, Safari 10.1+, Firefox 63+ |
| `requestAnimationFrame` | Canvas dot grid, cursor loop | All modern browsers |
| `createImageBitmap` | `image-slot.js` `toDataUrl()` | Chrome 50+, Safari 15+, Firefox 42+ |
| `canvas.toDataURL('image/webp')` | `image-slot.js` | Chrome/Edge; Safari 14+; Firefox 96+ |
| React 18 (`ReactDOM.createRoot`) | `support.js` boot | Falls back to `ReactDOM.render` if unavailable |
| `pointer-events` API (`setPointerCapture`) | `image-slot.js` reframe mode | Chrome 55+, Safari 13+, Firefox 59+ |
| `@media (hover: none)` | `.cc-cursor` hide rule | All modern browsers |

**`-webkit-text-size-adjust: 100%`** is applied to `body` globally to prevent iOS Safari from auto-scaling text in landscape mode.

**`backdrop-filter: blur(14px)`** is used on the nav. This is a visual enhancement — the nav remains functional if unsupported (older Firefox without the flag).

## Known Manual Test Areas

These areas require deliberate manual verification after any change because they have no automated coverage and have historically required fixes:

**Hero section vertical centering (≤765px):**
- At 481–765px, the hero must be centered with no bottom gap. The scroll indicator must appear at `bottom: 50px`.
- At ≤480px, the hero must fill the full viewport (`min-height: 100svh`) with no bottom gap and no scroll indicator visible.
- At ≤372px, hero padding-top must be `96px` to clear the nav.
- Test on a real device or DevTools device emulation with the browser chrome visible (not just the viewport toggle).

**Nav behavior at ≤372px:**
- Nav links must be hidden; burger icon must appear.
- Clicking the burger must toggle the mobile menu open/closed.
- Clicking a nav link inside the mobile menu must close the menu and smooth-scroll to the section.

**Language toggle:**
- Switching from EN to DE (and back) must update all visible strings including the typing animation roles, nav labels, contact form placeholders, and footer copy.
- The typing animation must reset (clear current text, restart from first role) on toggle.

**Contact form:**
- Submitting with all fields filled must POST to `sendMail.php` and show the success state (`sent: true`).
- The honeypot `website` field must be submitted but must not block a real user submission.
- The `sending` state must disable the submit button and show "Sending ..." label.
- Network failure must show the error message (`sendError: true`).

**`image-slot` component:**
- The hero photo and about photo must display the `assets/profile.png` fallback `src` when no user-dropped image is in `.image-slots.state.json`.
- In the omelette/editor runtime (`window.omelette.writeFile` present), drag-and-drop onto the slot must persist the image.
- In a plain browser (no omelette), the slot must be read-only — no empty-state "browse files" link, no Replace/Remove controls.

**Canvas dot grid:**
- Must render and animate on page load.
- Dots near the mouse cursor must glow green; dots far away must be dim grey.
- Must resize correctly on window resize without visual artifacts.

**Scroll progress bar:**
- The thin bar at the top of the page must fill left-to-right as the user scrolls from top to bottom.

**`dist/` sync:**
- After any change to `Portfolio.dc.html`, `image-slot.js`, or `support.js`, confirm the corresponding file in `dist/` is also updated before committing.
